# YatraFlow v0.81.0

This minor release promotes the design-system ownership batch and the private profile boundary to production. It is the first release cut after `test` and `main` were rejoined.

## Highlights

- **Every stylesheet family now has one owner.** The single stylesheet is an entry of 17 ordered modules. Tokens, the Landing hero, search and select styles, and the workspace header each live in the module that owns them. No rendered value changed.
- **The ownership rule is executable.** `npm run check:css` fails on an owned class declared outside its module, an unregistered stylesheet, a new file that defines tokens, a rising `!important` count, or a relative `url()` that no longer resolves. It runs inside `npm run verify`.
- **Public profile reads go through one boundary.** Public identity reads from `profile_cards` through `get_public_profile_cards`. Email, home city, languages, preferences, account dates and admin flags stay with the owner and authorized admins. Realtime carries public identity only. (#800)
- **A delayed payment webhook cannot restore access after a full refund.** Grants and refunds lock the same order, so a late delivery cannot outrun a refund. Duplicate deliveries remain safe.
- **Trip creation compares the budget target with the plan estimate.** The shortcut stays disabled until an estimate exists, and the rounded target covers it.
- **Every cover follows one rule:** the traveller's upload, then the artwork that fits the trip's places, then the saved emoji.
