YatraFlow — how should the map look?

Every panel below is a live map — same MapLibre GL v6 engine and keyless OpenFreeMap vector tiles the app ships with — drawn over the Kerala demo trip's real route: all 15 stops across 4 days, road-true geometry from OSRM (498 km). Panels 1–2 are today's shipped look; 3–8 are the candidates — including the dark twin any brand style needs.

The feature request picks three of them: panel 4 = 2D (Liberty, the proposed new default), panel 6 = Terrain (Liberty + hillshade), panel 7 = 3D hero (Liberty + real terrain, pitched). All three share one palette, so switching modes changes the camera and the relief — not the colours. (more colour, and terrain). Toggle the route overlay to compare like-for-like.

Stock swap · Bright

1-line change

OpenFreeMap's own "bright" style: blue water, green parks, warm road ramp. The cheapest possible colour win — flip one URL and every map in the app changes.

How: in TripMap, pass styles={{ light: "https://tiles.openfreemap.org/styles/bright", dark: "…/dark" }} — the mapcn wrapper already accepts style URLs (or inline specs) via prop, verified in its source.

Stock swap · Liberty

1-line change

OpenFreeMap's "liberty" — the classic OSM-carto lineage: cream land, vivid water, visible place hierarchy. Busier than bright; best if we want the map itself to feel like a travel atlas.

How: same one-prop swap as panel 3. Nothing else in the app changes — markers, routes, gestures are layers on top of whatever style is loaded.

Custom · YatraFlow brand palette

runtime recolour

Positron's geometry and labels, recoloured to the brand tokens at runtime: cream land, teal water, mist-green parks, saffron motorways. Minimalism stays — but it's unmistakably ours.

How: fetch positron's style JSON once, walk its layers and swap paint colours through a hex-lookup (what this page does live, in ~40 lines), pass the object as the styles.light inline spec. No style fork to host, no extra requests, theme-reactive for free. A dark twin = same map over the stock dark style.

Terrain mode — Liberty + hillshade

new source · keyless

Liberty (the proposed default) plus a hillshade layer from the AWS Terrain DEM. The Western Ghats read instantly — Cheeyappara's valley, Munnar's ridges — while the map stays flat, cheap and always-visible. Liberty's own relief raster fades out by zoom 6, so this fills the gap rather than doubling up.

How: one extra raster-dem source (s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png, free, no key, CORS verified) + one hillshade layer inserted before the first water/waterway layer. Works over any basemap; on Android this is the GPU-friendly terrain option.

3D hero — Liberty + real terrain

new source · heavier

The hero view on the same Liberty colours as the other two modes — switching to 3D changes the camera and the relief, not the palette. Pitched ~70° off the Munnar plateau down the ghat climb, where this route rises from 335 m at the foot to 2,054 m at Munnar and 2,676 m at Top Station (sampled live from the DEM). Drag to rotate.

How: the same DEM through map.setTerrain({ source: 'yf-dem', exaggeration: 1.8 }) + a pitched camera (MapLibre's default maxPitch is 60 — raised to 75 here). Relief only shows when tilted, and it costs more GPU — the Android caveat — so it ships as an explicit mode, never the default. Liberty's building-3d extrusions are minzoom: 14, so there's no building clash at trip scale.

8

Custom · YatraFlow brand — dark twin

runtime recolour

The same recolour applied to the dark style, because the app follows data-theme and a brand look without a dark twin would split the product. Deep navy-teal ground, teal water, saffron motorways — and light labels, which the stock dark style cannot do on its own (it ships dark-grey text).

How: identical mechanism, different lookup — the stock dark style only uses 22 distinct colours, so the twin is another table of the same size. It also has to repaint every label light, and dim the saffron ramp so it doesn't glare on black.
