Visual proposal · issue #415

Narrow Map layouts strand the planning rails below an off-screen map

Below the split breakpoint the Map tab stacks three full sections — map, the Day plan rail, and the Optional extras rail — so a tablet or a split laptop window shows exactly one at a time. Every pin↔candidate comparison costs a scroll up and a scroll down. This page mocks the fix: the map stays pinned, the rails become one tabbed sheet. All styling uses the app's own tokens (teal 500/600, --yf-poi-see violet, Sora + Plus Jakarta Sans, 18/12px radii, 40px touch floor).

The band the issue is about: a browser snapped to half a laptop screen. Map ~42%, sheet scrolls — no more page-scroll gymnastics.

Why one pattern, three sizes

  • Same anatomy everywhere: map fraction on top, grab, three tabs, state bar. Nothing to relearn between phone and split desktop.
  • The fraction is a token, not a guess: --map-sheet-split: 42% (38% under 480px), so the map never drops below ~230px of usable height.
  • Rail content is untouched: the two rails and the search box render inside the sheet's panes — one component, two containers (grid cell on desktop, sheet pane ≤1278px).
  • The fold still works: collapsing a rail just selects the other tab and shrinks the sheet's peek height.
Swipe is additive, not required. The sheet can be dragged between peek / half / full on touch — but every state is reachable from the tabs alone, so nothing depends on a gesture.
5

Proposal B — the alternative the issue allows (swipeable rail sheet)

Where it wins: landscape tablets with room to spare — the map keeps nearly everything and the rail docks as an edge sheet you swipe between Needs / Sights / Search. Where it loses: at 360px and narrow splits the edge sheet eats the map's width, and three horizontal pages are easier to lose state in than three tabs. It also needs gesture plumbing the tab pattern gets for free.

Recommendation: ship A, keep B as the ≥900px-landscape refinement. The issue allows either ("sticky top map plus a tabbed planning sheet; or a map plus swipeable rail sheet on larger tablets, only where each remains readable"). A covers every width with one grammar; B can layer on later for big tablets without changing A's structure — the panes are the same components.

What the fix must keep true (from the issue)

Desktop untouched

The 3-column .map-ideas-grid above 1278px is not restructured. The sheet exists only inside the narrow media block — new rules appended at the end of styles.css, so the line-keyed design-system baseline never moves.

State survives tabs

activeDayIndex, the open slot, the selected pin, the search query and the shortlist live one level up (or in the existing rail state), so switching tabs is a pure view change. A state test proves day / query / pin / shortlist survive.

Keyboard & screen reader

The tab strip is a real tablist — arrows move, Home/End jump, one roving tab stop — the same contract the #333 rail work shipped for the result lists. Panels keep their aria-labelledby pairing.

Touch floor & motion

Tabs and Add buttons stay ≥40px. Sheet drag/peek uses --motion-med + --ease-resize (both ends at rest — it resizes in place) with a prefers-reduced-motion opt-out; type stays on the 11px floor and the 400–800 ramp.

Z-ladder untouched

The sheet is in-flow layout, not a new overlay: --z-modal 100 and --z-dock 55 keep their meaning, and any popup the sheet opens (calendar, select) layers above it by the existing rules.

Honest map states

The pinned map keeps today's honesty: measured road vs dashed-amber estimate, quota-paused search says so, and a day with no placed stop shows no weather chip. Narrow layout changes none of those states — only who shares the viewport.

Tests the issue asks for

  • CSS regression coverage for the narrow layout, appended so the design-system baseline is not renumbered.
  • A state test proving sheet-tab switches preserve day, search, pin and shortlist.
  • No DOM-dependent map assertions — helpers and state, not rendered tiles. Verify at 360px, 768px and a split-desktop width, plus keyboard and reduced-motion passes.
